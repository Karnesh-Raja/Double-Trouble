# AgroSense Shelf-Life & Risk Model

Deterministic, explainable, no randomness, no LLM in any calculation. Same input always gives the same output.
Code: `src/engines/shelfLifeEngine.js`, `src/engines/riskEngine.js`. **Every number lives in `src/engines/modelConfig.js`.**

## 1. Inputs

| Input | Source | Valid range |
|---|---|---|
| `produceType` | shipment | any string (unknown types use the `default` profile) |
| `baselineShelfLifeHours` | shipment | > 0 and <= 2000 (Tomatoes: 120) |
| `temperature` (C) | telemetry (simulated) | -30 to 60 |
| `humidity` (%) | telemetry (simulated) | 0 to 100 |
| `transitMinutes` | telemetry (simulated) | 0 to 86400 |

Anything else is rejected with a field-level error (API returns 400). The engine never silently guesses.

## 2. The formula

```
degradationMultiplier = 1 + temperatureStress + humidityStress + transitStress
remainingHours        = baselineShelfLifeHours / degradationMultiplier
degradationPercentage = (1 - remainingHours / baselineShelfLifeHours) x 100
```

Perfect conditions give stress 0, multiplier 1, so the shipment keeps its full baseline life.
A multiplier of 6.65 means "this produce is ageing 6.65 times faster than normal."
Stresses are **added**, not multiplied, so no single factor can explode the result.

## 3. The three stresses (all linear, all configurable)

**Temperature stress (strongest).** Sum of (degrees inside each band) x (stress per degree):

| Band | Stress per degree C | Meaning |
|---|---|---|
| <= 4C | 0 | optimal |
| 4 to 8C | 0.3 | slightly warm |
| 8 to 12C | 1.0 | out of cold chain (limit is 8C) |
| above 12C | 1.5 | severe heat abuse |
| below 0C | +0.5 | freezing damage |

Multiplied by the produce's `temperatureSensitivity` (Tomatoes 1.0; Mangoes 0.8, Strawberries 1.25, Spinach 1.3 are illustrative demo values).

**Humidity stress.** Ideal band 70-80%: free. Up to 10 points outside: 0.05 per point (moderate). Beyond that: 0.10 per point (severe).

**Transit stress.** First 180 minutes free (a normal leg). Each extra hour adds 0.2, capped at 0.5 total.
The cap is deliberate: it keeps the factor simple and prevents "unrealistic exponential destruction."

**Expiry rule.** If hours in transit >= baseline hours, remaining = 0.

## 4. Risk thresholds (`calculateRisk(remainingHours)`)

| Remaining hours | Risk |
|---|---|
| > 72 | LOW |
| 48 to 72 (72 included) | MEDIUM |
| 24 to 48 (48 excluded, 24 included) | HIGH |
| < 24 | CRITICAL |

Risk depends only on remaining hours, because temperature and humidity are already inside that number.

## 5. Worked examples (generated by the engine; Tomatoes, 120h baseline)

| Scenario | Temp / Humidity / Transit | T stress | H stress | R stress | Multiplier | Remaining | Degraded | Risk |
|---|---|---|---|---|---|---|---|---|
| Normal | 4C / 78% / 180 min | 0 | 0 | 0 | 1 | **120h** (5d) | 0% | LOW |
| Slightly warm | 6C / 78% / 180 min | 0.6 | 0 | 0 | 1.6 | **75h** (3.1d) | 37.5% | LOW |
| At cold-chain limit | 8C / 78% / 180 min | 1.2 | 0 | 0 | 2.2 | **54.5h** (2.3d) | 54.5% | MEDIUM |
| Heat only | 12C / 78% / 180 min | 5.2 | 0 | 0 | 6.2 | **19.4h** (0.8d) | 83.9% | CRITICAL |
| **SPIKE (demo)** | **12C / 85% / 240 min** | **5.2** | **0.25** | **0.2** | **6.65** | **18h** (0.8d) | **85%** | **CRITICAL** |
| Humid | 4C / 95% / 180 min | 0 | 1 | 0 | 2 | **60h** (2.5d) | 50% | MEDIUM |
| Dry | 4C / 50% / 180 min | 0 | 1.5 | 0 | 2.5 | **48h** (2d) | 60% | MEDIUM |
| 24h transit | 4C / 78% / 1440 min | 0 | 0 | 0.5 | 1.5 | **80h** (3.3d) | 33.3% | LOW |

Demo by hand: temperature = 4 deg in the warm band x 0.3 + 4 deg in the abuse band x 1.0 = 5.2. Humidity = 5 points over 80% x 0.05 = 0.25.
Transit = 1 extra hour x 0.2 = 0.2. Multiplier = 1 + 5.2 + 0.25 + 0.2 = 6.65. Remaining = 120 / 6.65 = **18.05, shown as 18h**. CRITICAL (< 24h).

## 6. Output

```
{ remainingHours, remainingDays, degradationPercentage, riskLevel,
  factors: ["Elevated temperature exposure", "High humidity", "Extended transit duration"],
  contributions: { temperatureStress: 5.2, humidityStress: 0.25, transitStress: 0.2 },
  contributionSharePct: { temperature: 92, humidity: 4.4, transit: 3.5 },
  degradationMultiplier: 6.65, formula: "120h / (1 + 5.2 temp + ...) = 18h", ... }
```

## 7. Assumptions

1. Spoilage speeds up as temperature rises above the optimum, and speeds up faster once out of the cold chain.
2. The factors are independent, so their effects add.
3. The temperature bands, humidity band and produce sensitivities are **calibrated demo values**, chosen to be plausible and to reproduce the 120h to 18h demo. They are not laboratory measurements.
4. `transitMinutes` is total elapsed transit time at the moment of the reading.

## 8. Limitations (say these before the judges do)

- Not validated against real produce data. Real systems fit the curve (for example Arrhenius or Q10 kinetics) to lab or historical data.
- Each reading is evaluated on its own. It does not integrate exposure over time, so a past heat excursion is not "remembered" once temperature recovers. A production version would accumulate damage per interval.
- Transit stress is a capped penalty, not time actually subtracted from shelf life, so very long transits at ideal temperature are slightly optimistic. The expiry rule is the safety net.
- No ethylene, mechanical damage, ripeness stage or packaging effects.
- Produce profiles only scale temperature sensitivity.

## 9. Tuning

Edit `src/engines/modelConfig.js` only, then run `npm test`. Tests pin the demo outputs, so a change that breaks the 120h / 18h demo fails loudly.

## 10. Tests (`npm test`, 20 tests)

Normal, moderate temperature, high temperature, sub-zero, high and low humidity, long transit (capped), expiry, combined stress, determinism (1000 repeats),
monotonicity, produce profiles, config override, invalid telemetry (NaN, strings, out-of-range, missing, null), and all risk boundaries (72, 48, 24).

## 11. Explain it to a first-year student

> Think of fresh tomatoes as having a **120-hour life if kept perfectly cold**. Three things make them "age faster": **heat, wrong humidity, and a long journey**.
> We give each one a **penalty score**. Cold and normal means penalty 0. The hotter it gets, the bigger the penalty, and heat counts the most.
> Then we divide: **remaining life = 120 hours / (1 + all the penalties)**.
> Normal case: penalties are 0, so 120 / 1 = **120 hours (5 days), safe**.
> Spike case: heat adds 5.2, humidity 0.25, long trip 0.2, so 120 / 6.65 = **about 18 hours, critical**. The tomatoes are ageing 6.65 times faster.
> The same inputs always give the same answer, and every number sits in one settings file, so nothing is hidden or random.
> The AI never does this math. It only explains the result and recommends what to do.
